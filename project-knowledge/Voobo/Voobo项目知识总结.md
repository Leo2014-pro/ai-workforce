## 一、项目概览

### 1. 一句话定位
**Voobo 是一款"AI 原生"的数字货币交易平台**：用户不需要学习 K 线、下单、挂单等复杂操作，直接用自然语言（中文/英文）即可完成行情咨询与真实交易。

### 2. 核心场景
| 用户输入（示例） | AI 行为 |
|---|---|
| "BTC 还能买吗？" | 返回行情分析（理解 + 检索 + 生成） |
| "帮我买 100USDT BTC" | 识别交易指令 → 解析参数 → Function Call → 真实下单 |

### 3. 一期范围边界
- **支持的交易所**：Binance、OKX（仅此两家）
- **交易类型**：仅 Spot（现货）
- **明确不做（一期）**：自动交易、策略交易、网格、跟单、合约

### 4. 一期商业目标
> 验证「AI 聊天 + AI 交易 + 会员付费」三者结合的商业模式能否跑通。
> 变现与增长抓手：**订阅（会员 + AI 代币）+ 钱包（内部账户）+ 邀请（裂变返佣）** —— 此三者目前均未完全落地，是关键路径（见第七章分析）。

```

        │
     Gateway（网关）
        │

   ▼    ▼         ▼
```

- 与 FW（第三方托管/打款系统）联动：FW 授权、FW 打款、FW AI 接入（迭代）。

## 三、用户前端功能详解（12 模块）

### 3.1 登录/注册 —— ✅ 已完成

**功能列表口径**：邮箱登录、注册、忘记密码。

**登录**：邮箱 → 密码 →（开启 Google 验证则校验）→ 进入首页（AI 聊天）。
- 邮箱格式错误 → "邮箱格式错误"；密码错误 → "邮箱或密码错误"（防枚举）；
- **连续失败 5 次 → 限制登录 5 分钟**；Google 验证码错误 → "谷歌验证错误"。

**注册**：邮箱 + 邮箱验证码 + 密码 + 确认密码 + 昵称 + 协议勾选 → 注册成功自动登录。
- 登录密码 **≥8 位，须含一个数字 + 一个符号**；
- 邀请关系**只能基于邀请链接中的 ID 建立**（防刷，不允许手填邀请 ID）。

**忘记密码**：邮箱 → 验证码 → 新密码（强度规则同上）。

**分析**：功能完整、无进行中欠账项，可作为其他模块的参考基准。谷歌/Apple 第三方登录未进入本期功能范围。

### 3.2 资产概览 —— ✅ 已完成（OKX、币安）

**功能列表口径**：显示已对接第三方资产信息，**后续每对接一个第三方，都需要将资产在该列表展示**。
**分析**：这是"多第三方聚合资产页"的扩展性设计 —— 意味着新交易所/钱包接入时，资产展示属于接入清单的一部分（接口需可配置化）。FWF 授权账户资产也通过本页 + FWF 模块展示。

### 3.3 钱包 —— ⬜ 未开发（★ 全项目最高优先级欠账）

**功能列表口径**：内部账户，含 **AI 代币**和**美元**两种资产：
- **美元**：用于邀请返佣，或通过充值获得；
- **AI 代币**：通过购买会员或直接购买获得（AI 能力计费媒介）。
- 状态：**目前未开发，需要输出详细需求进行开发**。

**分析（关键依赖）**：钱包是三个商业环节的底层依赖 —— ①邀请奖励发放（美元）、②订阅/AI 代币计费、③充值。钱包需求未输出，直接阻塞"会员付费 + 邀请裂变"商业闭环的验证。**建议第一优先级补需求**。

### 3.4 邀请 —— 🟡 部分完成

**功能列表口径**：邀请关系和邀请奖励等数据展示。**邀请关系已完成，奖励还未完成**。

**详细规则（需求文档）**：
- 邀请方式：二维码 / 链接（`www.Voobo.com/?inv=xby1995`，长期有效、每人唯一）；
- 页面区块：邀请统计（付费/免费用户数）、二维码与链接、最近邀请（7 天 ≤10 条）、邀请记录（全部/会员/非会员筛选、分页）；
- 统计口径：付费 = 当前处于会员有效期；到期自动计入免费用户；
- **防刷铁律**：每人只绑一个邀请人，注册时建立；建立后**不可修改/解绑/转移**；已登录用户访问邀请链接**不建立**关系；邀请模块只建关系，**不负责奖励计算/发放**（平台统一配置）。

**分析**：关系链已就绪，但"奖励"两端都没闭环 —— 奖励发放规则需平台统一配置 + 钱包（美元返佣账户）未开发。邀请裂变要跑通，需同时落定这两项。

### 3.5 策略中心 —— ⬜ 需求调研阶段

**功能列表口径**：需求整理中，待后续补充。
**分析**：与一期"不做策略交易"的边界一致。属于探索型模块，风险低，待需求整理后再评估开发范围。

### 3.6 绑定账户 —— 🟡 OKX/币安已完成，FW 开发中

**功能列表口径**：通过 API KEY 方式绑定交易所账户，绑定后即可在 AI 聊天实现交易、查询等操作，后续不断增加新的第三方。状态：**已完成 OKX、币安对接，FW 正在开发中**。

**详细规则**：
- 填写 API Key + Secret（OKX 还需 Passphrase）→ 测试连接 → 绑定；支持解绑与状态查看；
- **同交易所可绑定多个账户**，账户**昵称全局唯一**（跨交易所不可重复），作为 AI 对话中的账户指代标识；
- AI 查询/下单时**先询问用户选择哪个账户**；
- 绑定时若 FW 账户已开启 Google 验证，需同步验证 FW 的 Google 验证码；
- 绑定属于资金安全操作：需交易密码 + Google/邮箱验证（见风控矩阵）。

**分析**：币安/OKX 绑定已可用；FW 绑定是当前进行项，完成后 FWF 模块数据源更完整。多账户昵称唯一 + AI 先问账户，是交易正确性的关键交互，需重点测试。

### 3.7 订单薄（= 需求文档"订单中心"）—— 🟡 初版对接完成

**功能列表口径**：显示第三方订单数据，并可以**点击跳转对应聊天消息板块**。初版对接完成，**界面还需调整**。
> 口径说明：功能列表称"订单薄"（应为"订单簿"），需求文档称"订单中心"，为同一模块。

**详细规则（需求文档 · 迭代重点）**：
- 定位：展示**全部成交记录**，两类来源：AI 执行下单 + **交易所手工下单（外部订单）**；
- 筛选：买卖方向（全部/买入/卖出）× 交易所（全部/Binance/OKX），默认按成交时间倒序；
- 按日期分组（Today / Yesterday / 具体日期），支持分页、筛选；
- 字段：买卖方向、交易对、交易所、成交数量、成交金额、成交均价、成交时间（yyyy-MM-dd HH:mm）、**下单账户昵称**；
- 颜色约定：Buy=绿、Sell=红（文档原始标注，需以设计稿确认）；
- 交互：外部订单点击弹框查看详情；Voobo 下单点击弹框锁定委托单数据并可**跳转对应聊天记录**（每笔订单关联唯一聊天上下文；聊天已删除则提示"聊天记录已删除"）。

**分析**：底层架构已完成（并发与扩展性优化过），当前欠账在 UI 层。**"订单↔聊天"双向可溯**是本产品差异化能力（交易可解释性），界面调整时应保住这条主线。

**安全矩阵（需求文档）**：
| 功能 | 邮箱验证码 | Google验证码 | 当前交易密码 | 后台审核 |
|---|---|---|---|---|
| 修改邮箱 | ✅ | 开启时必填 | ❌ | ❌ |
| 修改登录密码 | ✅ | 开启时必填 | ❌ | ❌ |

| KYC 认证 | ❌ | ❌ | ❌ | ✅（后台审核） |

**补充规则**：

- **身份密钥**：在 AI 对话时用于验证"不是钓鱼网站"（防钓鱼暗号机制，参考 FW 实现；迭代需求中的"验证谜语"同类）。

**分析**：身份密钥是针对"AI 对话钓鱼"场景的独有安全设计，完成后建议同步在对话引导中教育用户使用。

### 3.12 AI 聊天 —— 🟡 提币开发中（★ 全产品核心）

**功能列表口径**：查询资产、查询价格、下单（市价、限价）、查询订单、撤单、**提币**。**提币开发中，能力已实现，需要优化展示以及字段**。

**① 支持的指令（自然语言）**
- 买 100USDT BTC / 买 0.01 BTC（金额或数量两种计价）/ 卖全部 ETH；
- 查看资产 / 持仓 / BTC 行情 / 今天赚多少钱 / 最近订单 / 提币（白名单地址）。

**② AI 识别要素**：交易动作（BUY/SELL）、币种、数量、金额、交易所、账户。
> "买 100USDT BTC" → Action=BUY, Exchange=Binance, Symbol=BTCUSDT, Amount=100, Unit=USDT。

**③ 主流程**：用户消息 → AI 理解意图 → Function Call → 交易接口 → 交易所执行 → 返回结果 → AI 组织自然语言回复。

**④ 二次确认（安全设计）**：真实资金动作（下单/撤单/提币）不允许直接执行：
- AI 先回显：即将买入 100USDT BTC / 预计成交价 / 手续费 → 用户"确认"后执行；
- 下单确认弹框：**交易密码确认 + 滑动确认动画**（参考美国设计稿）；
- 也是后续**语音交互**的必备基础。

**⑤ Function Call 统一接口（AI 不可直连交易所）**：
| Function | 含义 |
|---|---|
| query_balance() | 查询余额 |
| query_position() | 查询持仓 |
| query_orders() | 查询订单 |
| place_order() | 下单 |
| cancel_order() | 撤单 |
| query_price() | 查询行情价格 |

**⑥ 单类型提示文案（勿写反）**：
- 市价单："市价委托是指以目前市场可获得的最优价格进行快速买卖。"
- 限价单："限价委托是指以特定或更优价格进行买卖，限价单不能保证执行。"
- 限价/市价后加"❗"图标，hover 展示。

**⑦ 异常话术**：
| 异常 | AI 回复 |
|---|---|
| 余额不足 | "当前余额不足，无法完成交易。" |
| 交易所 API 失效 | "交易所授权失效，请重新绑定 API。" |
| 交易失败 | "当前市场波动较大，请稍后重试。" |

**⑧ 导航引导（会议结论）**：聊天页空间有限，用**快捷入口（导航）代替长引导语**：查询资产 / 查询价格 / 下单 / 订单中心 / 提币。

**分析**：能力层（查询/下单/撤单）已实现且跑通，当前工作是**提币 + 展示/字段打磨**。提币是最高风险动作（资金离场），三重校验（资金密码 + Google/邮箱 + 二次确认）+ 白名单地址是硬约束，字段优化需与风控规则对齐。

## 四、底层能力（5 项）

### 4.1 对接中心化交易所 —— ✅ OKX、币安已对接

**能力矩阵（第一阶段目标：查询 → 下单 → 成交 → 提现闭环）**：
| 类别 | 接口能力 |
|---|---|
| 账户服务 | 查询账户资产、查询余额 |
| 行情服务 | 获取交易对、最新价格、K 线 |
| 交易服务 | 创建订单、撤单、查询订单、查询成交记录 |

- **状态机**：待支付 → 确认中 → 已支付 / 已失效 / 差异；到账幂等（一次且仅一次）；
- **异常口径**：少付/多付做差异订单线下处理；确认延迟/退款统一线下客服；KYT 关闭；数币到账链路独立建设（不复用法币链路）。
**分析**：订阅（会员付费）上线的前置依赖之一。

## 八、知识要点速查（11 条）

1. **一句话**：自然语言交易数字货币（Binance/OKX 现货），AI 只出 Function Call、交易一律系统执行、真实资金动作一律二次确认。
2. **功能架构**：用户前端 12 模块 + 底层能力 5 项 + 管理后台 3 组 9 表，共 26 个功能模块；按功能列表标注：完成 7 / 进行中 9 / 待开发 4 / 未标注 6。
3. **核心安全三层**：AI 不直连交易所 → 交易/提币二次确认 → 提币仅限白名单收款地址 + 资金密码（AI 提币三重校验：资金密码 + Google/邮箱 + 二次确认）。
4. **账户模型**：一个用户可绑多交易所多账户，昵称全局唯一；AI 下单/查询先问"用哪个账户"。
5. **钱包模型（待建）**：内部账户 = AI 代币（买会员/直接购买）+ 美元（充值/邀请返佣）—— 订阅与奖励的底层依赖。
6. **FW 联动**：授权绑定校验 FW 谷歌验证；FW 安全变更 → Voobo 授权全部过期（账户显示"已过期"）。
7. **密码规则**：登录密码 ≥8 位含数字+符号；交易密码 6 位数字；登录连错 5 次锁 5 分钟；身份密钥防 AI 对话钓鱼。
8. **订单中心**（功能列表称"订单薄"）= 全部成交记录（AI 单 + 外部手工单），按日期分组，可反查 AI 聊天上下文。
9. **后台 9 表**：用户（用户/KYC/聊天）+ 交易（记录/查询日志/交易所）+ 财务（支付订单列表[替代原会员购买记录]/钱包资产/充值记录）；撤单等敏感操作需二次确认并记操作日志。
10. **一期不做**：自动/策略/网格/跟单/合约；扩展方向：去中心化钱包、更多第三方接入（绑定账户与资产概览在设计上支持持续扩展）。
11. **数币收款（ForumPay，2026-09 定稿）**：业务 USD 计价、手续费用户承兑不展示；统一渠道管理覆盖数币+法币；支付订单归属三类（充值/会员/AI 代币）+ 后台备注（仅后台可见）；状态机：待支付→确认中→已支付/已失效/差异，到账幂等；少付多付走差异订单、延迟/退款线下客服、KYT 关闭；充值=余额充值（入账机制后续单独设计）。
