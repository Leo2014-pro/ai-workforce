## 二、知识变更明细

### 新增（长期知识）

| # | 知识点 | 内容 |
|---|---|---|
| 1 | 三资产钱包模型 | 内部账户 = 美金（2 位小数）+ AI 代币（整数）+ 令牌（整数）；令牌为独立新资产，计价暂 1 令牌=1 USD（临时口径），用途待定 |
| 2 | 六类钱包流水 | 充值、营销奖励、会员购买、令牌购买、赠送礼物、后台调整；AI 代币与令牌专项流水类型待定（模型预留扩展） |
| 3 | ⚠️ 后台调整下发口径 | 后台展示「后台调整」（含操作人/原因/单号）；**下发用户前端统一显示为「营销奖励」**，接口层必须做类型映射 |
| 4 | 资金路径铁律 | 所有支付资金一律先进美金余额、再从余额扣减购买；订阅页支持直接支付（入账[充值流水]→自动扣减到账[购买流水]一条流程） |
| 5 | 赠送口径 | 支持多人受赠；会员与令牌均可赠送且支持组合赠送；每受赠人一条赠送记录，整次赠送仅一条支付订单（一对多）；受赠人须为有效注册用户 |
| 6 | 后台资产调整 | 谷歌验证 + 调整原因必填 + 二次确认 + 操作日志；调整后余额不得为负；RBAC 按钮级权限 |
| 7 | 后台赠送记录页 | 字段：支付用户、赠送用户（每受赠人一行）、会员数量、令牌数量、时间、状态、关联支付订单号 |

### 修改（替代旧口径）

| 原知识 | 变更后 |
|---|---|
| 钱包 = 美元 + AI 代币两种资产（§3.3） | **三资产**：美金 + AI 代币 + 令牌 |
| 钱包状态「⬜ 未开发，需输出详细需求」 | **🟡 需求已定稿（2026-09-14），待开发** |
| 订阅状态「⬜ 待开发」 | **🟡 需求已定稿（2026-09-14），规则待定稿**（套餐/价格/权益仍不含） |
| 支付订单业务归属三类（充值/会员/AI 代币） | **四类**：新增**令牌购买** |
| 后台财务「钱包资产」预留表 | 由**会员资产页面**替代（三资产余额 + 流水查询 + 谷歌验证资产调整） |
| 「充值=余额充值，入账机制后续单独设计」 | 入账机制已定：支付成功即入美金余额（充值流水），后续购买从余额扣减 |
| 商业闭环阻塞点「钱包需求未输出」 | 阻塞解除；剩余决策件：会员权益/价格、邀请奖励规则 |

### 废弃

| 旧口径 | 说明 |
|---|---|
| 「钱包资产」表名与定位 | 由会员资产页面替代（同 ForumPay 归档中「会员购买记录」废弃口径一脉相承） |

### 保持不变

- 支付：ForumPay 数币收款口径（USD 计价、统一渠道管理、状态机、到账幂等、差异线下处理）全部沿用；
- 安全规范：敏感操作（资产调整）沿用「必填原因 + 二次确认 + 操作日志」既有后台规范，叠加谷歌验证；
- 订阅规则（套餐/价格/权益）与营销奖励发放规则仍为待定稿决策件，不在本次范围。

## 三、剩余占位事项（不阻塞开发）

5. 赠送「会员份数」与具体套餐的关联（随订阅规则定稿补充）。
